# Документация по API DeepSeek для создания чат-комплишнов

## Endpoint

```
POST https://api.deepseek.com/chat/completions
```

## Описание

Создаёт ответ модели для заданной чат-беседы.

## Запрос

### Обязательные параметры

| Параметр | Тип | Описание |
|----------|-----|----------|
| `messages` | `object[]` | Список сообщений, составляющих беседу. Минимальное количество: 1 |
| `model` | `string` | ID используемой модели. Возможные значения: `deepseek-chat`, `deepseek-reasoner` |

### Типы сообщений

Каждое сообщение в списке `messages` может быть одного из следующих типов:

1. **Системное сообщение**
   - `role`: "system" (обязательно)
   - `content`: содержимое системного сообщения (обязательно)
   - `name`: опциональное имя участника

2. **Сообщение пользователя**
   - `role`: "user" (обязательно)
   - `content`: содержимое сообщения пользователя (обязательно)
   - `name`: опциональное имя участника

3. **Сообщение ассистента**
   - `role`: "assistant" (обязательно)
   - `content`: содержимое сообщения ассистента (обязательно, может быть `null`)
   - `name`: опциональное имя участника
   - `prefix`: (бета) установите `true`, чтобы заставить модель начать свой ответ с содержимого переданного префикса. Для использования этой функции нужно установить `base_url="https://api.deepseek.com/beta"`
   - `reasoning_content`: (бета) используется для модели `deepseek-reasoner` в функции Chat Prefix Completion как входные данные для цепочки рассуждений в последнем сообщении ассистента. При использовании этой функции параметр `prefix` должен быть установлен в `true`

4. **Сообщение инструмента**
   - `role`: "tool" (обязательно)
   - `content`: содержимое сообщения инструмента (обязательно)
   - `tool_call_id`: ID вызова инструмента, на который отвечает это сообщение (обязательно)

### Необязательные параметры

| Параметр | Тип | Значение по умолчанию | Описание |
|----------|-----|------------------------|----------|
| `frequency_penalty` | `number` | 0 | Число от -2.0 до 2.0. Положительные значения штрафуют новые токены на основе их текущей частоты в тексте, снижая вероятность повторения одной и той же строки дословно. |
| `max_tokens` | `integer` | 4096 | Целое число от 1 до 8192. Максимальное количество токенов, которые могут быть сгенерированы в чат-комплишне. Общая длина входных токенов и сгенерированных токенов ограничена контекстной длиной модели. |
| `presence_penalty` | `number` | 0 | Число от -2.0 до 2.0. Положительные значения штрафуют новые токены на основе того, появляются ли они в тексте до сих пор, увеличивая вероятность того, что модель будет говорить о новых темах. |
| `response_format` | `object` | `{"type": "text"}` | Объект, определяющий формат вывода модели. Установка `{"type": "json_object"}` включает вывод JSON, который гарантирует, что сообщение, которое генерирует модель, является действительным JSON. **Важно**: при использовании вывода JSON вы также должны сами проинструктировать модель для создания JSON через системное или пользовательское сообщение. |
| `stop` | `string` или `string[]` | | До 16 последовательностей, на которых API остановит генерацию дальнейших токенов. |
| `stream` | `boolean` | `false` | Если установлено, будут отправляться частичные дельты сообщений. Токены будут отправляться как server-sent events по мере их появления, стрим завершается сообщением `data: [DONE]`. |
| `stream_options` | `object` | | Опции для потокового ответа. Устанавливайте только при `stream: true`. Включает поле `include_usage`, которое добавляет дополнительный чанк со статистикой использования токенов. |
| `temperature` | `number` | 1 | Температура сэмплирования от 0 до 2. Более высокие значения, например 0.8, делают вывод более случайным, а более низкие значения, например 0.2, делают его более сфокусированным и детерминированным. |
| `top_p` | `number` | 1 | Альтернатива сэмплированию с температурой, называемая nucleus sampling, где модель рассматривает результаты токенов с вероятностной массой top_p. Значение 0.1 означает, что рассматриваются только токены, составляющие верхние 10% вероятностной массы. |
| `tools` | `object[]` | | Список инструментов, которые модель может вызывать. В настоящее время в качестве инструмента поддерживаются только функции. Максимум поддерживается 128 функций. |
| `tool_choice` | `string` или `object` | Зависит от наличия tools | Управляет тем, какой инструмент (если есть) вызывается моделью. `none` - модель не будет вызывать инструмент, `auto` - модель может выбирать между созданием сообщения или вызовом инструментов, `required` - модель должна вызвать один или несколько инструментов. |
| `logprobs` | `boolean` | `false` | Возвращать ли логарифмические вероятности выходных токенов. |
| `top_logprobs` | `integer` | | Целое число от 0 до 20, указывающее количество наиболее вероятных токенов для возврата в каждой позиции токена, каждый с соответствующей логарифмической вероятностью. `logprobs` должен быть установлен в `true`, если используется этот параметр. |

## Ответ

### Поля ответа (без стриминга)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `string` | Уникальный идентификатор чат-комплишна. |
| `choices` | `object[]` | Список вариантов чат-комплишна. |
| `created` | `integer` | Временная метка Unix (в секундах) создания чат-комплишна. |
| `model` | `string` | Модель, использованная для чат-комплишна. |
| `system_fingerprint` | `string` | Этот отпечаток представляет конфигурацию бэкенда, с которой работает модель. |
| `object` | `string` | Тип объекта, всегда "chat.completion". |
| `usage` | `object` | Статистика использования для запроса комплишна. |

#### Структура объекта choice

| Поле | Тип | Описание |
|------|-----|----------|
| `finish_reason` | `string` | Причина, по которой модель прекратила генерацию токенов. Возможные значения: "stop", "length", "content_filter", "tool_calls", "insufficient_system_resource". |
| `index` | `integer` | Индекс варианта в списке вариантов. |
| `message` | `object` | Сообщение чат-комплишна, сгенерированное моделью. |
| `logprobs` | `object` | Информация о логарифмической вероятности для варианта. |

#### Структура объекта message

| Поле | Тип | Описание |
|------|-----|----------|
| `content` | `string` | Содержимое сообщения. |
| `reasoning_content` | `string` | Только для модели `deepseek-reasoner`. Содержимое рассуждений в сообщении ассистента перед окончательным ответом. |
| `tool_calls` | `object[]` | Вызовы инструментов, сгенерированные моделью, такие как вызовы функций. |
| `role` | `string` | Роль автора этого сообщения, всегда "assistant". |

#### Структура объекта usage

| Поле | Тип | Описание |
|------|-----|----------|
| `completion_tokens` | `integer` | Количество токенов в сгенерированном комплишне. |
| `prompt_tokens` | `integer` | Количество токенов в промпте. Равно prompt_cache_hit_tokens + prompt_cache_miss_tokens. |
| `prompt_cache_hit_tokens` | `integer` | Количество токенов в промпте, которые попадают в кэш контекста. |
| `prompt_cache_miss_tokens` | `integer` | Количество токенов в промпте, которые не попадают в кэш контекста. |
| `total_tokens` | `integer` | Общее количество токенов, использованных в запросе (промпт + комплишн). |
| `completion_tokens_details` | `object` | Разбивка токенов, использованных в комплишне. Включает поле `reasoning_tokens` - токены, сгенерированные моделью для рассуждений. |

### Ответ со стримингом

При использовании `stream: true` ответ представляет собой последовательность объектов `chat.completion.chunk`, отправляемых как server-sent events. Каждый чанк имеет следующие поля:

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `string` | Уникальный идентификатор чат-комплишна. Каждый чанк имеет один и тот же ID. |
| `choices` | `object[]` | Список вариантов чат-комплишна. |
| `created` | `integer` | Временная метка Unix (в секундах) создания чат-комплишна. Каждый чанк имеет одну и ту же временную метку. |
| `model` | `string` | Модель для генерации комплишна. |
| `system_fingerprint` | `string` | Этот отпечаток представляет конфигурацию бэкенда, с которой работает модель. |
| `object` | `string` | Тип объекта, всегда "chat.completion.chunk". |

#### Структура объекта choice в стриминге

| Поле | Тип | Описание |
|------|-----|----------|
| `delta` | `object` | Дельта чат-комплишна, сгенерированная потоковыми ответами модели. |
| `finish_reason` | `string` | Причина, по которой модель прекратила генерацию токенов. |
| `index` | `integer` | Индекс варианта в списке вариантов. |

#### Структура объекта delta

| Поле | Тип | Описание |
|------|-----|----------|
| `content` | `string` | Содержимое фрагмента сообщения. |
| `reasoning_content` | `string` | Только для модели `deepseek-reasoner`. Содержимое рассуждений в сообщении ассистента перед окончательным ответом. |
| `role` | `string` | Роль автора этого сообщения. |

## Пример использования

### Пример запроса CURL

```bash
curl -L -X POST 'https://api.deepseek.com/chat/completions' \
-H 'Content-Type: application/json' \
-H 'Accept: application/json' \
-H 'Authorization: Bearer <TOKEN>' \
--data-raw '{ 
  "messages": [ 
    { 
      "content": "Вы полезный помощник", 
      "role": "system" 
    }, 
    { 
      "content": "Привет", 
      "role": "user" 
    } 
  ], 
  "model": "deepseek-chat", 
  "frequency_penalty": 0, 
  "max_tokens": 2048, 
  "presence_penalty": 0, 
  "response_format": { 
    "type": "text" 
  }, 
  "stop": null, 
  "stream": false, 
  "stream_options": null, 
  "temperature": 1, 
  "top_p": 1, 
  "tools": null, 
  "tool_choice": "none", 
  "logprobs": false, 
  "top_logprobs": null 
}'
```

### Пример ответа (без стриминга)

```json
{
  "id": "930c60df-bf64-41c9-a88e-3ec75f81e00e",
  "choices": [
    {
      "finish_reason": "stop",
      "index": 0,
      "message": {
        "content": "Hello! How can I help you today?",
        "role": "assistant"
      }
    }
  ],
  "created": 1705651092,
  "model": "deepseek-chat",
  "object": "chat.completion",
  "usage": {
    "completion_tokens": 10,
    "prompt_tokens": 16,
    "total_tokens": 26
  }
}
```
